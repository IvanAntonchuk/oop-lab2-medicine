# Medicine

Виконав: Антончук Іван ІПС-31

Лабораторна робота №2 з ООП, варіант 4: «Лікарські препарати».

Java-додаток працює з XML-файлом лікарських препаратів:

- перевіряє XML за XSD-схемою;
- розбирає його трьома парсерами: SAX, DOM і StAX;
- сортує колекцію через `Comparator`;
- перетворює XML за допомогою XSL у XML зі зміненою структурою: препарати розкладаються по елементах за групою (`<antibiotic>`, `<analgesic>`, `<vitamin>`);
- повідомлення про роботу виводить через Logger (SLF4J + Logback).

Консольної взаємодії з користувачем немає: програма читає налаштування з файлу і пише хід роботи в лог.

## Модель даних

Препарат `Medicine` має назву, виробника-фарму, групу, список аналогів і список версій (форм випуску). У кожної версії є кілька виробників, а у виробника: сертифікат, упаковка і дозування.

| Клас | Поля |
|---|---|
| `Medicine` | id, назва, фарма, група, аналоги, версії |
| `Version` | форма випуску, виробники |
| `Manufacturer` | назва, `Certificate`, `MedicinePackage`, `Dosage` |
| `Certificate` | номер, дата видачі, дата закінчення, організація |
| `MedicinePackage` | тип упаковки, кількість, ціна |
| `Dosage` | одиниця виміру, доза, кількість прийомів на день |

Усі класи моделі незмінні, перевіряють вхідні дані в конструкторі (`IllegalArgumentException`) і копіюють колекції.

## Як працює програма

1. `Main` читає `config/app.properties` (або файл із першого аргументу запуску).
2. `Application` послідовно розбирає XML трьома парсерами. Перед розбором кожен парсер перевіряє файл за `data/medicines.xsd`.
3. Для кожного результату в лог виводяться назви препаратів у трьох сортуваннях: за назвою, за групою та назвою, за найменшою ціною.
4. `XslTransformer` застосовує `data/medicines-by-group.xsl` і записує результат у `output/medicines-by-group.xml`.

Фрагмент результату XSL-перетворення:

```xml
<Medicines>
    <analgesic>
        <Medicine id="...">...</Medicine>
        <Medicine id="...">...</Medicine>
    </analgesic>
    <antibiotic>
        <Medicine id="...">...</Medicine>
        <Medicine id="...">...</Medicine>
    </antibiotic>
    <vitamin>
        <Medicine id="...">...</Medicine>
        <Medicine id="...">...</Medicine>
    </vitamin>
</Medicines>
```

JDK підтримує лише XSLT 1.0, тому групування зроблено методом Мюнхена через `xsl:key`.

## Запуск

Потрібно: JDK 17 або новіший, Maven (в IntelliJ IDEA він вбудований).

- Застосунок: запустити клас `ua.antonchuk.medicine.Main` з кореня проєкту (робоча директорія має бути коренем, бо шляхи в налаштуваннях відносні).
- Тести і звіт покриття: `mvn test` (в IntelliJ: Maven → Lifecycle → test).
- Звіт JaCoCo: `target/site/jacoco/index.html`.

### Налаштування

Файл `config/app.properties`:

```properties
xml.path=data/medicines.xml
xsd.path=data/medicines.xsd
xsl.path=data/medicines-by-group.xsl
output.path=output/medicines-by-group.xml
```

Щоб використати інший файл налаштувань, його шлях передають першим аргументом запуску `Main`.

### Логування

Логи йдуть у консоль і у файл `logs/medicine.log` (налаштування в `src/main/resources/logback.xml`). Каталоги `logs/` та `output/` додані до `.gitignore`.

## Опис класів

Усі класи знаходяться в пакеті `ua.antonchuk.medicine` та його підпакетах.

### Корінь пакета

| Клас | Призначення |
|---|---|
| `Main` | Точка входу. Визначає файл налаштувань (за замовчуванням `config/app.properties`, або перший аргумент запуску), завантажує конфігурацію, створює й запускає `Application`. Якщо виникає помилка, логує її і перекидає виняток далі, щоб процес завершився з ненульовим кодом. |
| `Application` | Оркеструє роботу. Отримує через конструктор конфігурацію, список парсерів і `XslTransformer` (завдяки цьому в тестах їх замінюють моками Mockito). Метод `run()` розбирає XML кожним парсером, логує колекцію у трьох сортуваннях і запускає XSL-перетворення. Статичний метод `create(AppConfig)` збирає справжні об'єкти: один `XmlValidator`, парсери SAX, DOM, StAX та `XslTransformer`. |

### Пакет `config`

| Клас | Призначення |
|---|---|
| `AppConfig` | Незмінний об'єкт із чотирма шляхами: до XML, XSD, XSL і до вихідного файлу. Метод `load(Path)` читає їх з `.properties`-файлу (UTF-8), обрізає пробіли й перевіряє, що кожне значення задане і є коректним шляхом. |
| `ConfigException` | Виняток (`RuntimeException`) для помилок налаштувань: файл не прочитано, властивість відсутня або шлях недопустимий. |

### Пакет `model`

Предметна модель. Усі класи незмінні (`final`, поля `final`), перевіряють дані в конструкторі й кидають `IllegalArgumentException`, мають `equals`, `hashCode` і `toString`.

| Клас | Призначення |
|---|---|
| `Medicine` | Лікарський препарат: id, назва, фарма, група, список аналогів і непорожній список версій. Забороняє дві версії з однаковою формою випуску. Списки копіюються, тому зовні змінити їх не можна. |
| `Version` | Версія препарату: форма випуску і непорожній список виробників. |
| `Manufacturer` | Виробник певної форми: назва, сертифікат, упаковка і дозування. |
| `Certificate` | Сертифікат: номер, дати видачі й закінчення, організація. Дата закінчення має бути пізнішою за дату видачі. |
| `MedicinePackage` | Упаковка: тип, кількість і ціна (`BigDecimal`). Ціна `85.50` і `85.5` вважаються рівними. |
| `Dosage` | Дозування: одиниця виміру, доза та кількість прийомів на день. Доза й кількість мають бути додатними. |
| `MedicineGroup` | Перелік груп: `ANTIBIOTIC`, `ANALGESIC`, `VITAMIN`, `ANTIVIRAL`, `ANTISEPTIC`, `ANTIHISTAMINE`. |
| `MedicineForm` | Перелік форм випуску: `TABLET`, `CAPSULE`, `POWDER`, `DROPS`, `SYRUP`, `OINTMENT`. |
| `PackageKind` | Перелік типів упаковки: `BLISTER`, `BOTTLE`, `BOX`, `TUBE`, `SACHET`, `AMPOULE`. |
| `DosageUnit` | Перелік одиниць дозування: `MCG`, `MG`, `G`, `ML`. |

### Пакет `util`

Допоміжні класи зі статичними методами. Екземпляри не створюються.

| Клас | Призначення |
|---|---|
| `Validation` | Перевірки аргументів: не `null`, непорожній текст (повертається обрізаним), додатні `int`, `double` та `BigDecimal`, копія списку без `null`-елементів, непорожній список. Помилки мають однотипні повідомлення на кшталт `Field must not be null or blank`. |
| `EnumParser` | Перетворює текст на константу переліку без урахування регістру (`antibiotic` дає `ANTIBIOTIC`). Для невідомого значення кидає виняток із зрозумілим повідомленням. |
| `ValueParser` | Розбирає дати, цілі, дійсні та десяткові числа з тексту. Помилку формату обгортає в `IllegalArgumentException` з назвою поля. |

### Пакет `parser`

Спільна логіка розбору XML.

| Клас | Призначення |
|---|---|
| `MedicineParser` | Інтерфейс парсера: `List<Medicine> parse(Path xmlFile)`. |
| `AbstractMedicineParser` | Шаблонний метод. `parse` спочатку перевіряє файл за XSD, потім відкриває потік, викликає абстрактний `parseDocument`, обгортає всі помилки у `MedicineParseException` і логує кількість розібраних препаратів. Нащадки реалізують лише сам розбір. |
| `MedicineEventHandler` | Єдиний обробник подій розбору. Отримує `startElement`, `characters` та `endElement` і за ними збирає препарати через збирачі. Його використовують усі три парсери, тому логіка не дублюється. |
| `ModelBuilder<T>` | Базовий клас збирачів (шаблонний метод). `build()` створює об'єкт і перетворює `IllegalArgumentException` з моделі на `MedicineParseException`. |
| `MedicineBuilder` | Збирає `Medicine` з рядкових даних XML: id, назва, фарма, група, аналоги й версії. |
| `VersionBuilder` | Збирає `Version`: форма випуску та виробники. |
| `ManufacturerBuilder` | Збирає `Manufacturer`: перетворює рядки на дати, числа й переліки та створює сертифікат, упаковку й дозування. |
| `XmlNames` | Константи з назвами тегів і атрибутів XML. |
| `XmlValidator` | Компілює XSD один раз у конструкторі, а `validate(Path)` перевіряє XML-файл за схемою. Доступ до зовнішніх ресурсів заборонено. |
| `XmlFactories` | Фабрики для SAX, DOM, StAX і XSLT із безпечними налаштуваннями: заборона DOCTYPE, secure processing, вимкнений доступ до зовнішніх DTD, схем і стилів. |
| `MedicineParseException` | Виняток (`RuntimeException`) для всіх помилок читання, розбору та валідації XML. |

#### Підпакети парсерів

| Клас | Призначення |
|---|---|
| `sax.SaxMedicineParser` | Розбір подієвим парсером SAX. Внутрішній клас-адаптер передає події `DefaultHandler` у `MedicineEventHandler`. |
| `stax.StaxMedicineParser` | Розбір потоковим парсером StAX. У циклі зчитує події `XMLStreamReader` і передає їх у `MedicineEventHandler`. |
| `dom.DomMedicineParser` | Будує дерево DOM, а потім рекурсивно обходить його і викликає ті самі методи `MedicineEventHandler`. |

### Пакет `comparator`

| Клас | Призначення |
|---|---|
| `MedicineComparators` | Набір компараторів `Comparator<Medicine>`: `BY_NAME` (за назвою без урахування регістру), `BY_GROUP_THEN_NAME` (за групою в порядку оголошення переліку, потім за назвою) і `BY_CHEAPEST_PRICE` (за найменшою ціною серед усіх упаковок препарату, при рівності за назвою). |

### Пакет `transform`

| Клас | Призначення |
|---|---|
| `XslTransformer` | Компілює XSL-стиль один раз у конструкторі. Метод `transform(Path, Path)` виконує перетворення в пам'яті й лише після успіху створює каталог і записує вихідний файл, тому при помилці напівготового файлу не лишається. |
| `StrictErrorListener` | Слухач помилок XSLT: попередження йдуть у лог, а помилки перетворюються на виняток замість друку в `stderr`. |
| `XmlTransformException` | Виняток (`RuntimeException`) для помилок XSL-перетворення та запису результату. |

## XSD-схема

`data/medicines.xsd` описує корінь `Medicines` з елементами `Medicine`. Схема задає:

- шаблон ідентифікатора `MED-001` (`xs:ID`);
- переліки груп, форм випуску, типів упаковки й одиниць дозування;
- обмеження на числові значення й дати;
- унікальність форм випуску в межах одного препарату (`xs:unique`).
